# テスト

## いつも実行するもの

```sh
npm test          # サーバーと画面の部品のテスト（Node だけで動く）
npm run test:tz   # 日付の計算を、3つの地域の時刻（タイムゾーン：UTC、東京、ロサンゼルス）で確かめる
```

Node のバージョンは 22 以上。Mac・Windows・Linux のどれでも実行できる。

## ブラウザーで確かめるもの

```sh
npm run test:browser
```

Chromium で実際に画面を動かして確かめる。`test/browser/` にある8つのテストを、順に実行する。1つでも失敗したら、そこで止まる。7つ目の前に、`npm run build` と同じビルドを自動でする（`dist/` を作り直す）。

| ファイル | 確かめること |
|---|---|
| `image-error-check.py` | 開けない画像があるノートを開いても、ノートの中身が変わらない |
| `mermaid-link-check.py` | Mermaid の図に書いたリンクが、描いた図に残らず、図を押してもどこへも移らない。パネルと同じ通信の制限（`src/panel-csp.json`）の下で、図の画像や見た目の設定のURLを読み込みに行かない。描けなかった図のエラーの絵が、図の枠の外に残らない |
| `calendar-width-check.py` | 右の列のカレンダーが、狭い幅でもはみ出さない |
| `wrap-indent-check.py` | 長い箇条書き・チェック項目・番号付きの項目が折り返したとき、2行目以降が記号のあとの本文にそろう（タブやスペースでの入れ子、引用の中の項目、カーソルが項目の行にあるとき、幅を変えたときも）。測り直しが止まり、1行目の本文の位置は直す前と変わらない。段落と引用の段落は字下げしない。Ctrl+Space をエディターが使わない。長いノートで速く下へ・上へスクロールしたあとも、見えている項目がそろう。画面の外の行は、スクロールして画面に入れてから測る。入れ子の縦の線がタブの区切りと一致する。見出し、行間1.5と1.7、閲覧、ソース、広い幅でもそろう |
| `props-enter-check.py` | ノートの情報の欄（タイトルや日付などを書く欄）で、Enter キーや、日付を選ぶ部分が正しく動く |
| `panel-check.py` | 保存できないときに本文の上に出るお知らせ、別のノートを開く前の確認、大きすぎる画像、ゴミ箱に入れるためのコマンドがないとき、古い下書きの片付け |
| `ai-context-check.py` | 「開いているノートをAIに伝える」。起動時にオフなら空の内容で上書きする、スイッチの保存と送信、Vaultの場所と選んだ行の番号（選択が外からの書き換えで消えたときの送り直しを含む）、読み直しとスイッチの重なり、2つの画面でのオフ、タブを閉じる前の上書き、受け方（標準・文字だけ・OpenAI の印・受けない・断る・空の上書きだけ断る）ごとの送り方と知らせ。ビルドした `dist/panel.html` を使う |
| `panel-csp-check.py` | ビルドした本物のパネル（`dist/panel.html`。通信の制限が入っている）を、Codexアプリの代わりをするテスト用のページ（`host-harness.mjs` と `host-server.mjs`）の中で開き、ふだん使う機能を順に動かす。動かす機能は、数式、図、フォルダーの中の画像、コードの色づけ、外へのリンク、内部リンク、編集と保存、画像の貼り付け、「履歴」、カレンダーと「今日のノート」、ノートを探す、新しいノート、名前の変更、移動、ゴミ箱、「設定」。そのあと、ノートの情報の欄と表の編集、パスのコピー、「履歴」から戻すこと、「設定」の保存、週と月のノート、フォルダーの作成と名前の変更、下書きの反映も動かす。確かめるのは3つ。どの操作でも、通信の制限に止められたものがない。ネット上の画像は読み込みを試さず「画像を開けません」と出る。ファイルを指定して開いたタブでも保存できる。Codexアプリが付ける制限（sandbox など）は再現していない |

必要なもの：

- このパッケージの `node_modules`（`npm install` のあと）
- Python 3.10 以上と、Python 版の Playwright と Chromium。仮想環境（venv）に入れるのがおすすめ。

```sh
python3 -m venv .venv
. .venv/bin/activate              # Windows では .venv\Scripts\activate
python3 -m pip install playwright # Windows では python3 の代わりに python
python3 -m playwright install chromium   # Windows では python3 の代わりに python
```

`npm run test:browser` は、Playwright の入った Python を `python3`、`python`、`py` の順に探す。仮想環境を使うときは、その仮想環境に入った状態で実行する。

テスト用のノートは、毎回一時的なフォルダーに作る。実際のノートには触らない。画面を撮った画像を残したいときは、`npm run test:browser -- <フォルダー>` のようにフォルダーを渡す（`calendar-width-check.py`、`wrap-indent-check.py`、`panel-check.py`、`panel-csp-check.py` が、そこに画像を残す）。`panel-csp-check.py` でゴミ箱へ移すものは、Mac のゴミ箱ではなく、一時的なフォルダーに移すようにしている。

`panel-check.py` のゴミ箱を確かめる部分は、Mac で出る文言（`/usr/bin/trash` や Finder）を前提にしている。ほかの部分は Windows でも同じように動くはずだが、Windows では実行して確かめていない。

## 実際のノートで確かめる道具（いつもは実行しない）

```sh
node test/corpus.mjs <Vault のコピー>
```

フォルダーの中の全部のノートを、開いて保存しても1バイトも変わらないことと、1か所を編集してもほかが変わらないことを確かめる。

**ノートに書き込むので、必ずコピーに使う。** 本物の Vault には使わない。保存の直前に作る控えは、一時的なフォルダーに作る。

結果は最後に JSON で出る。失敗があっても終了コードは 0 のままなので、`failureCount` が 0 かどうかを見る。
